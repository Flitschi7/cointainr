# Domain Docs

## Layout

This repository uses a single-context layout: `GLOSSARY.md` at the repository
root and architectural decision records under `docs/adr/`.

## Before exploring

- Read the root `GLOSSARY.md` when present.
- Read decisions under `docs/adr/` that apply to the area being explored.
- If these documents are absent, proceed silently. Create them lazily through
  domain modeling when terms or decisions are actually resolved.

## Vocabulary and decisions

Use glossary terms when naming domain concepts in issues, proposals,
hypotheses, and tests. Reconsider invented synonyms; note genuine vocabulary
gaps for the domain-modeling skill.

Explicitly identify any proposal that contradicts an existing ADR, including
the decision identifier and the reason to revisit it.
